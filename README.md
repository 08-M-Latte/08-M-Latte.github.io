## 紹介

これはシンプルな個人サイトで、派手な演出はほとんどありません。  
デザイン思想は「簡潔さを最優先」とし、モダンな UI スタイルと合理的なレイアウト設計を採用しています。

サイトテンプレートを編集するときに、コードを丁寧に探して文章を置き換える必要があり、面倒に感じたことはありませんか？このプロジェクトのモジュラー設計はその問題をうまく解決します。サイトタイトル、管理者情報、SNS リンク、サイト情報など、使用前に必ず変更が必要になる項目は、コード内に直接ハードコードせず、「サイト設定」にまとめています。サイトの内容やデザインに特別な要件がない場合は、JSON 設定ファイルを編集するだけで簡単に使えます。  
設定ファイルを使うもうひとつの利点は、バージョンアップが非常に簡単なことです。更新時も設定ファイルの値を手動で調整するだけで、基本的な内容をシームレスに切り替えられます。  
サイト設定の変更方法については、以下の [使い方 / サイト設定の変更](#サイト設定の変更) セクションをご覧ください。

サイトの本文やお知らせ欄は [markdown-it](https://github.com/markdown-it/markdown-it) を使って Markdown を HTML にレンダリングしています（GitHub の README のような感覚です）。この方式の利点は、サイト本文の作成がかなり簡単になることと、レンダラーが HTML をフィルタしないことです（つまり、短い Markdown 文書を書くだけで、複雑なページコンテンツを作れます！）。

このプロジェクトのコードは読みやすく、コンテンツと HTML スタイルが分離されているため、自由に自分の好みに合わせて編集しやすくなっています。  
サイトの基盤はシンプルな最小構成だけで、好きな内容をこの上に追加していけます。大規模プロジェクトの制約や複雑さに縛られにくいです。

このプロジェクトは現在、リファクタリング後の最初のメジャーバージョンです。今後も現行のデザイン思想を保ちながら、多くのモジュール機能が追加される予定です。興味があれば Star やフォローをお願いします。\(>▽

何か問題があれば Issue を立ててください。追加してほしい機能や提案があれば、ディスカッションを立ち上げてください。

## 使い方

このプロジェクト自体はそこまで複雑ではありませんが、いくつか知っておくと便利な点があります。

### サイト設定の変更

サイト設定ファイルは `config.json` で、プロジェクトのルートディレクトリ（`/`）にあります。JSON 形式なので、編集時は JSON の構文ルールに従う必要があります。  
プロジェクトにはすでにこの設定ファイルが含まれており、利用可能な設定項目とデフォルト値が記載されています。必要に応じて値を変更するだけで使えます。サイトはページを読み込むたびにこの設定ファイルを取得し、解析して必要な箇所に適用します。

> [!CAUTION]  
> 注意！設定ファイルの項目を削除しないでください（たとえ使う予定がなくても）。そうすると、たちまち「Null Pointer」エラーを招きます。  
> 本当に不要だと判断した項目がある場合は、`""` に設定してください。  
> バージョンアップの際も設定ファイルを同期させる必要があります。 [ここ](https://github.com/ChengCheng0v0/ACG-Home/compare) で現在のバージョンタグと最新バージョンタグを選び、`config.json` を比較して差分を確認できます。古いバージョンの設定を新しいバージョンへ手動で移行してください。

### Web ページ内の任意の場所に Markdown を挿入する

実はとても簡単です。`markdown-content` クラスを持つ要素をどこにでも置けば OK です。例：

```html
<div class="markdown-content" src="./assets/markdown/content-page.md"></div>
```

このコードでは、純粋な `div` 要素でコンテンツを囲んでいます。markdown-it によって変換された HTML 要素はこの `div` の中に挿入されます。  
`src` 属性は、レンダリング対象の `.md` ファイルの相対パスまたは絶対パスを定義します。対象はローカル URL でもリモート URL でも構いません。レンダラーは `fetch` を使って Markdown ソースを取得し、レンダリングします。

レンダラーはページの DOM が読み込まれたタイミングで、ページ内のすべての `.markdown-content` 要素を探し、その `src` に指定された内容を描画するため、ページ内のどこにでもこの要素を置けます。

このプロジェクトには、レンダリング対象の Markdown ファイルが 2 つ含まれています：`/assets/markdown/content-page.md` と `/assets/markdown/announcement.md`。これらはそれぞれメインコンテンツエリアとサイドバーのお知らせカードの Markdown を保持しています。

レンダラーのさらに高度なカスタマイズについては、[markdown-it.js](https://github.com/markdown-it/markdown-it) の公式ドキュメントをご覧ください。

### メインコンテンツ領域の Markdown を書くときのベストプラクティス

レイアウト上の都合から、本文を編集する際は各見出しの前の段落の後に `---` 区切り線を入れるのがおすすめです。カスタム CSS の区切り線スタイルを使うと、ページ全体がより調和して見えます（もちろん、好みのスタイルに合わせて省略しても問題ありません）。
